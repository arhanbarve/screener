## Process — what was fixed today

The trader has now failed on **4 of 9 market days** (07-27, 07-30, 08-03, 08-04)
plus 2 gate failures (07-23, 07-28), for **3 clean completions out of 9**. Every
crash shared one cause and one amplifier:

- **Cause:** the job runs while the Mac is asleep. `launchd`'s 09:00 fire only
  DarkWakes the machine, the job held no power assertion, and macOS slept within
  seconds — killing the API streaming connection. Duration was never the tell:
  07-31 succeeded over 3h11m while 07-30 died in 6m45s.
- **Amplifier:** `run_trader.sh` stamped the date *before* the session so a crash
  could never retry. Every transient disconnect became a permanently skipped day,
  invisibly.

Fixed in `824c0ed`:

- Session runs under `caffeinate -imsu`.
- `StartInterval 900` in the launchd plist, so a session begins as soon as the Mac
  is next awake inside the 08:30–15:45 ET window rather than only at 09:00.
- Stamp now written *after* the session. On a crash, `trader_cli activity-today`
  decides: no orders today → retry; any orders → stamp and never retry; check
  itself failed → stamp conservatively.
- Attempts capped at 5/day.
- Paper page reports per-day run cadence, so a lost day is visible the same
  afternoon instead of never.

**Known remaining limit:** the 08-03 log shows `Clamshell Sleep`. macOS enforces
clamshell sleep regardless of `caffeinate`, and `-s` only applies on AC power, so a
closed laptop on battery at 09:00 can still fail. The retry path covers it by
starting when the lid next opens inside the window; reliable 09:00 execution needs
AC power or a different host.

**Not yet fixed:** journaling still happens *last*, so a session that trades and
then dies still loses its record — which is exactly what happened on 08-03 and was
only recoverable because `claude-mem` had incidentally captured the analysis.
