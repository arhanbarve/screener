silently fails leaves the position strictly worse off than never running the
sync at all**, and it is happening on a schedule, at the same time of day, to
the same names. I re-armed manually tonight, but the fix belongs in
`sync-stops` — the cancel leg should not commit unless the replacement is
confirmed. Noting it here rather than changing code mid-session.

A second, separate mechanical finding from tonight, worth recording because it
will recur: **a resting protective stop blocks any buy in the same symbol.**
Alpaca treats stop-sell plus buy as a potential wash trade and rejects the
second order outright. That means adding to a floor-protected position is never
a single command — it is cancel, buy, wait for the fill, re-arm — and the middle
of that sequence is an unprotected window. Any future plan to add to an existing
holding needs to budget for that sequence up front instead of discovering it at
the order, which is what cost me the BFLY add tonight.
