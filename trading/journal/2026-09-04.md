### 7. Cancel SPY's stop to clear the wash-trade block — PROCESS, and it was not in the plan

**This is a deviation from the Planned orders table below, recorded here rather than done
quietly.** The plan said "nothing needs its stop cancelled." That was wrong, and it was
wrong for a reason I had already written down yesterday and failed to carry forward.

`buy SPY --qty 13` was rejected outright:

```
403: {"code":40310000,"existing_order_id":"db12e26c-...",
"message":"potential wash trade detected. use complex orders",
"reject_reason":"opposite side market/stop order exists"}
```

Alpaca will not accept a buy in a symbol that already has a resting sell stop. The 09-03
entry's Decision 5 called this out and made "cancel SPY's stop as the FIRST action" a process
rule; I dropped it from tonight's carry-forward list because it was filed under "what worked"
rather than "what to do next time." **Cost: nothing, because the reject is hard and loud.
That is the only reason this was cheap.**

Sequence run: `cancel-stops SPY` (cancelled `db12e26c-…` only; explicitly left ETON, TXG and
VLO alone, as `left_alone` in the response confirms) → buy accepted.

**The consequence is real and I am naming it rather than burying it: SPY is unprotected
overnight.** `sync-stops --apply` was run and could not restore the floor — the resting *buy*
limit triggers the same wash-trade rule in the opposite direction:

```
403: ... "reject_reason":"opposite side limit order exists.
use complex/limit/stop_limit orders"
```

So the $745.12 floor on 56 shares cannot exist while the buy rests. It will be restored by
the scheduled 09:40 ET `sync-stops` after the buy fills, as it was on 09-02 and 09-03. The
exposure window is tonight plus the first ten minutes of the session, on a position 3.5%
above its floor. I accept it because the alternative is not buying, but **this is a
structural defect in the workflow, not a one-off**: on any session where I add to a position
that already has a floor, that floor is off for ~17 hours. The fix is a `stop_limit` or
bracket/OCO order — Alpaca's own error message says so — and it is worth building rather than
re-accepting monthly.
